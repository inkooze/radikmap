# План реализации — Карта РГРТУ v1.2 (Масштабное обновление и оптимизация)

## Подтверждённые решения (Confirmed Decisions)

- **Разделение страниц Карты и Расписания**: Карта (`index.html`) и Расписание (`schedule.html`) разделяются на самостоятельные страницы (по аналогии с `editor.html`), а верхний центральный язычок **«Расписание» / «На карту»** сохраняется на своём месте и работает как прямая ссылка для переключения между ними (с поддержкой deep-ссылок вида `schedule.html?type=group&name=546` и автоматическим редиректом старых ссылок `index.html?view=schedule...`).
- **Вращение карты под разными углами**: На мобильных устройствах вращение выполняется жестом **двумя пальцами**, а на десктопных — удержанием **Ctrl + левая кнопка мыши** (с появлением кнопки-компаса для сброса ориентации на север и сохранением горизонтальной читаемости подписей кабинетов).
- **Выбор учебной недели в расписании**: В левой боковой панели прямо над заголовком **«Расписание»** размещается компактная кликабельная строка серым шрифтом в едином стиле интерфейса (например, `02.11.2026 · числитель ▾`), позволяющая переключать учебную неделю (по умолчанию всегда выбирается текущая неделя).
- **Маршруты через улицу и узлы графа**: В редакторе графа (`editor.html`) добавляется новый тип узла **«Улица»** (`outdoor`) с собственным контрастным цветом, визуально отличимым от узлов коридора, лестниц и входов, чтобы вы могли вручную разметить уличные точки. В панели маршрута на карте добавляется чекбокс **«Также через улицу»** (включён по умолчанию).

## 1. Архитектура v1.2 и разделение страниц (`index.html`, `schedule.html`, `editor.html`)

Разделение монолитного интерфейса на независимые страницы уменьшит объём DOM и ускорит первичный рендер каждой страницы: `index.html` не будет держать в памяти тяжёлую разметку таблиц расписания, а `schedule.html` не будет инициализировать Leaflet и загружать SVG-планы этажей до перехода пользователя на карту.

```
+-------------------------------------------------------------------------+
|                        Сервер (Node.js / Express)                       |
|  • HTTP Gzip/Brotli сжатие + ETag / Cache-Control заголовки             |
|  • Прямой парсер расписания групп/преподавателей + индекс аудиторий     |
|  • Предвычисленная матрица частотности аудиторий по кафедрам (O(1))     |
|  • Telegram Bot (кнопки «Карта» / «Расписание» + чат с «ИИ'шкой»)       |
+-------------------+-------------------------+---------------------------+
                    |                         |
       +------------+------------+   +--------+------------------+
       |                         |   |                           |
       v                         v   v                           v
+--------------+         +-------------------+           +---------------+
|  index.html  | <=====> |   schedule.html   |           |  editor.html  |
|  Карта РГРТУ |  Язычок | Расписание РГРТУ  |           | Редактор графа|
|  • SVG этажи |  сверху | • Выбор недели    |           | • Островки UI |
|  • Вращение  |         | • Сегодня/Завтра  |           | • Тип «Улица» |
|  • Маршруты  |         | • Полные пары     |           | • Смена типа  |
|  • «ИИ'шка»  |         | • Ссылки в карту  |           |   узла в 1 клик|
+--------------+         +-------------------+           +---------------+
```

- **Переход с расписания в карту**: При клике на аудиторию (например, `ауд. 337 С`) или кнопку «Показать на карте» в `schedule.html` происходит переход на `index.html?room=<id>`, где сразу открывается нужный корпус, этаж и карточка выбранной аудитории.
- **Обратная совместимость ссылок**: Если пользователь открывает старую ссылку `index.html?view=schedule&type=group&name=546`, страница мгновенно перенаправляет его на `schedule.html?type=group&name=546`.

## 2. Полное исправление парсера расписания (проблема группы 546 и других групп)

### Причина пропажи пар в текущей версии
Сейчас расписание групп и преподавателей собирается только путём «обратной инверсии» расписания аудиторий (`schedule-frame/classroom`). Из-за этого теряются:
1. **Пары без указания конкретной аудитории** — например, в субботу у гр. 546 `Учебная практика, доц. Гостин А.М.` (в расписании вуза аудитория не указана, поэтому ни одна страница аудитории эту пару не содержит).
2. **Пары в спецпомещениях без преподавателя** — например, `Элективные дисциплины по физической культуре и спорту, Спортзал С` (отсутствует ФИО преподавателя + нестандартное название зала).
3. **Лабораторные с делением на подгруппы (`п.г. 1`, `п.г. 2`) или несколькими преподавателями / аудиториями** — например, `Лаб. Вычислительная математика` у гр. 546 в `ауд. 50 С` и `ауд. 50а С` (а также `50с С`), где в одной ячейке таблицы идут несколько блоков или нестандартный регистр литеры корпуса (`50 С`, `50а С`).

### Решение
1. **Прямая загрузка официальной сетки группы и преподавателя с `rasp.rsreu.ru`**:
   - При запросе `/api/entity-schedule?type=group|lecturer&name=...&date=...` сервер напрямую обращается к официальной странице `https://rasp.rsreu.ru/schedule-frame/group?faculty=...&group=...&date=...` (или `lecturer?subFaculty=...&lecturer=...&date=...`) по ID из справочника и кэширует результат по ключу `(type, name, date)`.
   - Одновременно со страницы извлекается список всех доступных учебных недель из `<select name="date">` (с датами понедельников).
2. **Обновлённый парсер ячеек расписания**:
   - Корректно разбирает ячейки, содержащие несколько записей (разделённых `<br>`, `<hr>` или несколькими блоками подгрупп `п.г.`), не склеивая и не отбрасывая их.
   - Сохраняет пары **без преподавателя** (например, физкультура в `Спортзал С`), пары **с несколькими преподавателями** (перечисляя всех через запятую и делая каждого кликабельным) и пары **без аудитории** (например, `Учебная практика`, где поле аудитории остаётся пустым и аккуратно отображается без битой ссылки).
   - Нормализует сопоставление аудиторий с картой (`50 С`, `50а С`, `50с С`, `Спортзал С`), чтобы клик по любой из этих аудиторий в расписании безошибочно открывал соответствующее помещение на карте.

## 3. Выбор учебной недели и метки «Сегодня» / «Завтра»

- **Селектор недели над заголовком «Расписание»**:
  - В левой панели `schedule.html` непосредственно над заголовком `Расписание` выводится аккуратная серая строка в фирменном стиле: `ДД.ММ.ГГГГ · числитель` (или `знаменатель`) со стрелочкой выбора.
  - По клику открывается компактный выпадающий список учебных недель семестра (по умолчанию выбрана **текущая неделя**, отмеченная точкой/меткой «Текущая»).
  - При смене недели мгновенно подгружается расписание на выбранную дату с автоматическим пересчётом дат дней недели (`Понедельник 9 ноября`, `Вторник 10 ноября` и т.д.) и чётности недели (`числитель` / `знаменатель`).
- **Бейджи «Сегодня» и «Завтра»**:
  - В шапках таблиц расписания (и для групп/преподавателей, и для аудиторий) помимо синего бейджа **«СЕГОДНЯ»** добавляется аккуратный бейдж **«ЗАВТРА»** для следующего календарного дня (с учётом реально выбранной учебной недели — бейджи показываются только на тех датах, которые действительно совпадают с сегодняшним и завтрашним числом).
- **Исправление белого фона при горизонтальном скролле таблиц на мобильных**:
  - Для `.weekly-table-wrap` и `.schedule-main` добавляется `overscroll-behavior-x: contain`, синхронизируется фоновый цвет контейнера, самой таблицы и липкой колонки времени (`var(--surface)` / `var(--bg)`), чтобы при свайпе влево-вправо до упора на iOS/Android никогда не обнажалась белая полоса.

## 4. Обновлённая разговорная «ИИ'шка» и аналитика аудиторий кафедр

### Полуразговорный характер и адаптация к тону пользователя
- **Поддержка живого диалога**: «ИИ'шка» распознаёт приветствия и разговорные реплики («Привет», «Здравствуй», «Как дела?», «Спасибо», «Кто ты?», «Что умеешь?»), помнит контекст предыдущих сообщений диалога (например, если спросить «А где у 546 следующая пара?», а затем «Проложи туда маршрут») и отвечает на составные вопросы.
- **Зеркалирование тона собеседника**:
  - При нейтральном или дружелюбном обращении отвечает тепло, бодро и по-студенчески дружелюбно.
  - Если собеседник общается резко, саркастично или грубо, «ИИ'шка» не отвечает шаблонными извинениями, а отвечает в том же колком/сухом ключе с характером, при этом по-прежнему выдавая точный ответ по делу.

### Запрос «Помещения кафедры <КАФЕДРА>» (без нагрузки на сайт)
- Во время фоновой пересборки индекса расписания (`rebuildScheduleIndex()`) на сервере **один раз** предвычисляется легковесная хеш-таблица `departmentRoomsIndex`:
  1. **Закреплённые помещения кафедры** — кабинеты, преподавательские и лаборатории из `rooms.json`, принадлежащие данной кафедре по названию/описанию.
  2. **Топ аудиторий по частоте пар кафедры** — сервер суммирует количество учебных пар всех преподавателей данной кафедры (по данным `lecturers-meta.json`) в каждой аудитории и сортирует их по убыванию частоты.
- Когда пользователь спрашивает у «ИИ'шки» (на сайте или в Telegram-боте) например *«помещения кафедры ЭВМ»* или *«аудитории САПР ВС»*, ответ возвращается за **O(1)** из готового индекса в двух блоках:
  - Прямые помещения кафедры (с кнопками перехода на карту);
  - Блок **«В этих аудиториях часто преподаёт каф. <КАФЕДРА>»** с интерактивными чипами самых часто используемых аудиторий.

## 5. Карта: вращение, центрирование подписей, зум и маршруты

1. **Вращение карты под любым углом (`0°–360°`)**:
   - **Мобильные устройства**: жест вращения двумя пальцами (вычисление изменения угла вектора между двумя точками касания `touchstart` / `touchmove` одновременно с pinch-зумом).
   - **Десктоп**: удержание клавиши `Ctrl` + перетаскивание левой кнопкой мыши.
   - При угле поворота `bearing !== 0°` в плавающем островке управления появляется кнопка **компаса** со стрелкой, повернутой на текущий угол; клик по ней плавно возвращает карту в исходное положение (`0°`).
   - Все подписи кабинетов и иконки на карте компенсируют угол поворота (`--map-rotation: -Xdeg`), оставаясь горизонтальными и легко читаемыми под любым ракурсом.
2. **Исправление «уплывания» номеров кабинетов при отдалении карты**:
   - Вместо пересчёта пиксельных смещений при каждом зуме координаты каждой подписи жёстко привязываются к визуальному центру полигона комнаты (`polylabel` / ограниченный bbox-центроид в координатах SVG) с `iconSize: [0, 0]`, `iconAnchor: [0, 0]` и центрированием строго через `transform: translate(-50%, -50%) rotate(var(--map-rotation, 0deg))`. Подписи остаются строго внутри своих кабинетов на любом масштабе.
3. **Начальное приближение карты на мобильных по ширине корпуса**:
   - При открытии на мобильном экране (`<= 768px`) начальный масштаб рассчитывается по горизонтальному габариту здания (`fitBounds` по ширине активного корпуса с учётом верхних и нижних отступов UI), чтобы план этажа сразу занимал удобный, крупный масштаб.
4. **Статичный масштаб интерфейса (запрет авто-зума браузера при вводе)**:
   - Все поля ввода получают эффективный размер шрифта не менее `16px` на мобильных экранах + корректные настройки viewport и `touch-action: manipulation`, чтобы iOS Safari и Android Chrome никогда не масштабировали сам интерфейс при фокусе на поиск, при этом сама карта свободно зумится и вращается.
5. **Подсветка строки поиска только в режиме «ИИ'шка»**:
   - Убирается синяя обводка и свечение `.omni-bar` при обычном клике/фокусе на поле поиска. Синяя акцентная подсветка включается исключительно тогда, когда активирован режим **«ИИ'шка»** (`body.ai-mode-active`).
6. **Ползунок (`чёрточка`) мобильных нижних панелей**:
   - На всех нижних шторках (`.panel-drag-bar`, `.user-dropdown-drag-pill`) реализуется полноценное перетаскивание через `Pointer Events` (`pointerdown`, `pointermove`, `pointerup`, `setPointerCapture`) с `touch-action: none` на области ползунка: удерживая чёрточку пальцем, пользователь плавно тянет панель вверх или вниз на нужную высоту (с фиксацией в удобных состояниях или закрытием при свайпе в самый низ).
7. **Чекбокс маршрута «Также через улицу»**:
   - В панели построения маршрута добавляется галочка **«Также через улицу»** (по умолчанию включена).
   - Если пользователь снимает галочку, алгоритм Дейкстры исключает все узлы графа с типом `outdoor` («Улица») и строит маршрут исключительно внутри крытых переходов и коридоров корпуса.

## 6. Редизайн редактора графа (`editor.html`)

Редактор графа приводится к современному визуальному языку основного приложения:
- **Плавающие островки вместо старой верхней шапки**:
  - Левый верхний островок: кнопка возврата на карту, выбор корпуса (`ГК` / `АК`) и переключатель этажей (`0–5`).
  - Центральный островок инструментов: режимы **«Выбор»**, **«+ Узел»**, **«Связь»**, **«Удалить»** + выбор типа создаваемого узла.
  - Правый верхний островок: переключатель темы и кнопка **«Сохранить граф»** со счётчиком узлов и рёбер.
- **Новый тип узла «Улица» (`outdoor`) с собственной цветовой кодировкой**:
  - **Коридор (`corridor`)** — синий (`#3b82f6`);
  - **Улица (`outdoor`)** — ярко-бирюзовый / изумрудно-голубой (`#06b6d4`) с контуром, чтобы точки улицы мгновенно отличались от коридорных точек;
  - **Лестница (`stair`)** — оранжевый (`#f59e0b`);
  - **Вход (`entrance`)** — зелёный (`#10b981`).
- **Быстрая смена типа уже существующего узла**:
  - При выделении любого узла на карте или в боковом списке инспектор позволяет **в один клик поменять его тип** (например, переключить точку с «Коридор» на «Улица») без удаления узла и пересоздания его связей.

## 7. Telegram Mini App (Fullscreen Safe Area) и Telegram-бот

1. **Учёт системных плашек Telegram в полноэкранном режиме (`Main App`)**:
   - При запуске внутри Telegram WebApp считываются системные отступы `tg.safeAreaInset.top` и `tg.contentSafeAreaInset.top` (а также CSS-переменные `--tg-safe-area-inset-top` и `--tg-content-safe-area-inset-top` с гарантированным минимальным отступом в режиме `isExpanded` / `fullscreen`).
   - Все верхние плавающие элементы (`.schedule-corner-tab`, `.floating-top-right`, мобильная строка поиска) автоматически смещаются ниже кнопок **«✕ Закрыть»** и **«⌄ ⋯»** мессенджера.
2. **Две постоянные кнопки в Telegram-боте (`Карта` и `Расписание`)**:
   - В нижнем меню бота (`ReplyKeyboardMarkup` с `resize_keyboard: true, is_persistent: true`) вместо одной кнопки размещаются две кнопки в ряд: **«🗺 Карта»** (открывает `index.html`) и **«📅 Расписание»** (открывает `schedule.html`).
3. **«ИИ'шка» прямо в чате Telegram-бота**:
   - Любое текстовое сообщение пользователя в чате с ботом (если это не команда `/start` и не 6-значный код привязки профиля) передаётся напрямую в движок «ИИ'шки» с сохранением истории диалога пользователя в Telegram.
   - Бот отвечает тем же умным ответом (с расписанием, свободными кабинетами, помещениями кафедр и быстрыми инлайн-кнопками для открытия нужного кабинета или расписания в Mini App).

## 8. Глубокая оптимизация под капотом (Ревизия v1.2)

1. **Серверная производительность и неблокирующий ввод-вывод**:
   - Подключение потокового HTTP-сжатия (`gzip` / `brotli` через встроенный модуль `zlib`) для всех JSON-ответов, HTML/CSS/JS и особенно SVG-планов этажей (размер передаваемых SVG уменьшается в **4–6 раз**).
   - Перевод сохранения `users.json` и `schedule-cache.json` с синхронного `fs.writeFileSync` (блокирующего основной поток Node.js) на асинхронную буферизованную запись с атомарным переименованием (`writeFile` во временный файл + `rename`).
   - Добавление `ETag` и `Cache-Control` для статических ассетов и планов этажей.
2. **Мгновенное переключение этажей и предвычисление геометрии**:
   - Кэширование загруженных и распарсенных SVG-планов этажей в памяти клиента + фоновая предзагрузка (`requestIdleCallback`) соседних этажей после загрузки первого этажа, чтобы переключение этажей происходило мгновенно без сетевой задержки.
   - Вычисление центров полигонов комнат один раз при загрузке этажа (с кэшированием координат), исключающее повторные вызовы `getBBox()` при зуме и вращении карты.

Ниже — подборка улучшений, которые отлично дополнят версию 1.2. **Отметьте в комментариях те пункты, которые вам нравятся, и я включу их в реализацию:**

1. **Таймер обратного отсчёта до конца пары / перемены в плашке статуса**:
   - В зелёной/красной карточке статуса («Сейчас идёт пара» / «Сейчас перемена») добавить живой поминутный счётчик: например, *«До конца пары: 23 мин»* или *«Пара начнётся через 12 мин»* с тонкой полоской прогресса текущей пары.
2. **Умная кнопка «Куда мне сейчас?» для авторизованных студентов и преподавателей**:
   - Если в профиле пользователя указана его учебная группа (или ФИО преподавателя), на карте рядом с поиском появляется компактная подсказка с его текущей или ближайшей парой (например, `Следующая: ауд. 337 С в 09:55`) — в один клик она подсвечивает нужную аудиторию и строит маршрут от ближайшего входа.
3. **Экспорт расписания в календарь смартфона (`.ics`) или картинкой (PNG)**:
   - В шапке расписания группы/преподавателя рядом с кнопкой ссылки `🔗` добавить кнопку выгрузки расписания выбранной недели в стандартный файл календаря `.ics` (для Apple Calendar / Google Calendar / Яндекс.Календаря).
4. **Прямая ссылка на построенный маршрут (`Поделиться маршрутом`)**:
   - В панели активного маршрута («Откуда → Куда») добавить кнопку копирования ссылки вида `index.html?from=entrance_main&to=1_337`, чтобы староста или преподаватель мог скинуть одногруппникам готовый маршрут прямо до нужной двери.
5. **Режим «Свободные аудитории на выбранную пару и день»**:
   - В карточке быстрых тегов и в «ИИ'шке» позволить искать свободные аудитории не только «прямо сейчас», но и на конкретную пару (например, *«Свободные аудитории сегодня на 3 паре на 2 этаже»*), чтобы студентам было удобно искать тихое место для подготовки или проведения собрания.
6. **PWA-кэширование карты и последнего открытого расписания (Офлайн-режим)**:
   - В корпусах с толстыми стенами мобильный интернет иногда пропадает. Легковесный Service Worker сохранит планы этажей, граф маршрутов и последнее просмотренное расписание группы в кэше устройства, чтобы карта, поиск кабинетов, маршруты и своё расписание открывались даже без сети.
